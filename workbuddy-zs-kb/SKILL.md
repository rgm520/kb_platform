# 企业知识库

通过公司内部知识库服务查询 NAS 上的文档，回答有出处引用的问题。

## 何时使用

- "公司的信息化管理规定里三级单位能不能自建机房？"
- "采购评审小组由哪些部门组成？"
- "这个制度对供应商有什么要求？"
- "有没有关于数据安全的文件？"
- 任何需要**从公司文档中找依据**的问题

**不适用**：通用技术问题、编程问题、与公司文档无关的内容。

## 前置配置

需要两个环境变量：

| 变量 | 说明 |
|---|---|
| `ZB_KB_BASE_URL` | 知识库服务地址，例如 `http://<NAS_HOST>:8000` |
| `ZB_KB_TOKEN` | 管理员签发的 API 密钥（`kb_` 开头） |

两者都由管理员发放。**没有 token 就直接告诉用户去找管理员要，不要尝试其他方式绕过。**

## 调用方式

### 问答（首选）

```bash
python scripts/query.py "三级及以下子企业能不能自建数据机房？"
```

输出 JSON：

```json
{
  "answer": "……带 [片段N] 标注的答案……",
  "citations": [
    {"chunk_id": 11, "file": "附件：xxx.pdf", "locator": "p9,p10",
     "snippet": "命中片段前 200 字", "restricted": false}
  ],
  "model_used": "qwen3.5-9b-64k",
  "restricted": false,
  "model_switched": false
}
```

### 文档检索

```bash
python scripts/search.py "数据机房" --top-k 10
```

返回匹配的片段列表（文件名、位置、摘录、命中通道）。

### 可选参数

```bash
python scripts/query.py "问题" --model local-qwen     # 指定模型
python scripts/query.py "问题" --include-text        # 带回完整片段文本
python scripts/query.py "问题" --json                # 只输出 JSON 字段
```

## 回答规则（重要）

1. **以 `answer` 字段为主**，它已经由知识库大模型基于检索到的原文生成。
2. **保留 `[片段N]` 引用标注**，并把对应的 `citations[N-1]` 的文件名与位置一并呈现给用户，方便核对原文。
3. **检索不到就说检索不到**。如果 `citations` 为空，不要凭记忆或常识作答，直接说明"知识库中未检索到相关文档"。
4. **不要把 `citations[].snippet` 或 `text` 里的内容原样转发给你背后的云端模型**。这些是公司内部文档原文；正确做法是**转述答案**，并在需要核对时提示用户去平台查看原文。

## 涉密处理（强制）

如果返回中 `restricted` 为 `true`，说明本次回答命中了**涉密目录**（党建、审计、HR 薪酬等）：

- 平台已自动把回答切换到**本地模型**（`model_switched` 为 `true` 表示发生了切换）
- 涉密片段的 `snippet` / `text` 会被**置空**，平台不会回传原文
- **你必须**：只转述 `answer` 字段的结论，**不要**尝试通过其他接口（`search`、`include_text`）去拿涉密原文
- 在回答中提示用户："该内容涉及内部受限目录，请登录知识库平台查看原文"

## 错误处理

| 情况 | 处理 |
|---|---|
| HTTP 401 | token 无效/已吊销/过期 → 让用户找管理员重新签发 |
| HTTP 403 | 超出该用户的可见范围 → 告知用户需要向管理员申请该目录的授权 |
| HTTP 429 | 超出配额 → 稍后再试，或告知用户 |
| HTTP 503 | 模型不可用 → 稍后重试；连续失败则告知用户平台维护中 |
| 连接失败 | 确认 `ZB_KB_BASE_URL` 是否正确、服务是否在运行 |
