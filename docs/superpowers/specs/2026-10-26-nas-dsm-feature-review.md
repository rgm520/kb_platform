# NAS（群晖 DSM）功能拆解与借鉴清单

日期：2026-10-26
对象：`http://192.0.2.19:5000/`（群晖 DSM，主机名 `nas`，站名「某公司大综合系统」）
目的：拆清这个 NAS 平台有哪些能力，判定哪些对我们「企业知识平台（2.0）」有借鉴价值、
哪些能靠 AI 超越、哪些明确不做。

## 0. 拆解方法（可复核）

| 手段 | 拿到什么 |
|---|---|
| 浏览器登入（zhaosen） | 桌面布局、14 个已安装套件、可见的 4 个应用（按用户授权） |
| 桌面「主菜单」 | 全站套件清单（不受本人授权限制） |
| `SYNO.API.Info`（Web API） | **532 个接口 / 28 个域** 的能力全景（最权威） |
| 控制面板 | 22 个设置组 |
| 逐个套件看结构 | File Station / 资源监控 / 日志中心 / DSM 说明 / 套件中心 / 存储管理器等 |

> 注：zhaosen 是普通用户，看不到控制面板之外的多数套件界面，因此以 API 清单补全。

## 1. DSM 的六层能力地图

### L1 外壳（桌面）
- **桌面**：壁纸 + 彩色应用图标 + 图标下文字 + 顶部居中搜索框 + 左上「主菜单」+ 右上角
  （通知铃铛 / 账户 / 小组件 / 搜索）
- **通知中心**：主动推送「管理员账户易遭暴力破解，建议停用 admin」这类安全建议
- **套件中心**（应用市场 + 条款 + 安装/更新/卸载）
- **帮助中心**（DSM 说明：帮助文章 + 教程 + 常见问题 + 兼容性）
- **多窗口**：应用以窗口打开、可最大化、可拖拽、可并存

### L2 文件域
- **File Station**：共享文件夹树（可嵌套，如 `nas/video`）、面包屑（可编辑路径）、
  工具栏 `新增/上传/操作/工具/设置`、列表列（名称/大小/文件类型/修改日期）、
  右键菜单、拖拽、回收站、属性、预览、压缩/解压、校验（MD5）
- **文件服务**：SMB3 / NFS / FTP(SFTP) / AFP / WebDAV / Rsync / 服务发现
- **共享管理**：共享文件夹、加密共享、加密密钥管理、权限与**权限报告**、配额、快照
- **外部挂载**：挂载远端（CIFS/FTP/SFTP…）与云盘（VFS：Google Drive 等）

### L3 身份与接入
- 用户与群组、域/LDAP/SSO/OIDC、用户家目录、个人配额
- **应用权限**（`AppPortal.AccessControl`）：按用户授予套件权限
- **API 体系**：`SYNO.Core.API`（服务账号 + 密钥）、`SYNO.OAUTH.*`（OAuth 客户端/令牌/日志/范围）
- 安全：密码策略（强度/过期/历史）、2FA（OTP/TOTP）、安全密钥（WebAuthn）、自动封禁、登录历史

### L4 索引与知识
- **索引服务**（媒体索引）：缩略图、视频转码、索引目录、调度
- **Universal Search**：全局文件搜索 + Spotlight 预览 + 书签 + 搜索历史 + 应用索引
- 快照与历史版本

### L5 运维与可观测
- **资源监控**：性能（总览/CPU/内存/网络/磁盘/存储空间/LUN/NFS 实时图）、进程、连接、限速、设置
- **日志中心**：概述（图表 + 最近 50 条）/ 日志 / 通知；按日期、时间、级别、主机、分类、程序、消息过滤
- **事件调度器**（定时任务）、**任务计划**、通知渠道（邮件/短信/移动推送/Webhook/自定义变量）
- 备份与快照复制（Hyper Backup / Active Backup / 快照复制）

### L6 硬件与系统（NAS 专属）
控制面板 22 组：共享文件夹、文件服务、用户与群组、域/LDAP、连接性、外部访问、网络、
安全性、终端机与 SNMP、系统、信息中心、登录门户、区域选项、通知设置、硬件和电源、
外接设备、更新和还原、服务、Synology 帐户、应用程序权限、索引服务、任务计划；
外加存储管理器（磁盘/池/卷/Btrfs 校验/SMART/闪存缓存）、iSCSI/SAN Manager、
证书与 Let's Encrypt、DDNS/QuickConnect/VPN/端口转发。

## 2. 我们平台现状对照

| 能力 | 我们有 | 说明 |
|---|---|---|
| 桌面图标导航 | ✅ | 刚改成 DSM 风格（SVG 图标 + 顶部搜索框 + 主菜单） |
| 全局搜索 | 🟡 | 桌面搜索框（文件名 + 正文），刚做；无预览浮层/书签/历史 |
| 文件浏览（树/面包屑/双视图/排序分组/多选/右键/上传/预览/下载/删除进回收站） | ✅ | 比 DSM 多了正文搜索与知识联动 |
| 回收站 | ✅ | 只记平台内删除（DSM 也有） |
| 文档看板（解析进度/统计卡/重复件/已跳过/重跑） | ✅ | **DSM 没有**，这是我们的差异化 |
| 知识图谱 + 实体归一 | ✅ | **DSM 没有** |
| AI 问答（多路召回 + RRF + 重排 + 引用 + 反馈 + 轨迹） | 🟡 | 迭代 1 待做重排/改写/引用可信度 |
| OCR（扫描件） | ✅ | DSM 的媒体索引只做缩略图/转码 |
| 存储接入（多源/凭据加密/扫描三态） | ✅ | 刚做完；DSM 的对应物是「共享文件夹 + 文件服务」 |
| 目录授权（grants ∪ 老范围，统一入口） | ✅ | DSM 是共享级 ACL，我们细到子目录 |
| 审计（调用审计 + 检索轨迹 + 反馈） | 🟡 | 有记录，无"给用户看的审计视图"，无外发 |
| API 接入（密钥 + 智能体 + 调用手册 + 飞书 bot） | ✅ | 比 DSM 的 API 更聚焦；**缺 OAuth 客户端/令牌/范围** |
| 通知中心 | ❌ | 无站内通知、无邮件/企微通道 |
| 任务与计划中心 | ❌ | 计划任务只在 Windows 侧，用户看不到 |
| 帮助中心 | 🟡 | 有 API 调用手册（给 AI 的），没有给使用者的帮助 |
| 对外分享链接 | ❌ | 只能平台内授权访问 |
| 收藏夹 / 最近访问 | ❌ | |
| 压缩/解压、批量打包下载 | ❌ | |
| 配额 | ❌ | |
| 文件版本历史 / 快照 | ❌ | 只有整库备份 |
| 密码策略 / 2FA / 自动封禁 | ❌ | 只校验长度 ≥8 |
| 平台自身健康可视（队列/失败率/吞吐） | ❌ | 管理台没有运行态页 |
| LDAP/AD/SSO | ❌ | |
| 硬件运维（磁盘/RAID/固件/UPS/iSCSI/媒体转码） | ❌ | **明确不做**（见 §5） |

## 3. 值得抄的交互模式（按价值排序）

| # | 能力 | DSM 怎么做的 | 我们的抄法 | 成本 |
|---|---|---|---|---|
| 1 | **通知中心** | 顶栏铃铛 + 主动安全建议 + 事件推送 | 顶栏铃铛；管理台「通知」页；事件源：解析失败、共享掉线、扫描完成、授权变更、有人提问 | 低 |
| 2 | **平台健康页**（我们的"资源监控"） | 资源监控的实时图 + 进程/连接 | 管理台加「运行状态」：服务存活、解析队列深度、索引吞吐、近 24h 失败率、最近错误 | 低 |
| 3 | **任务与计划中心** | 事件调度器 + 任务计划 | 把现有 3 个计划任务 + 解析/OCR 队列暴露成一张表：状态、上次跑、下次跑、耗时、失败原因 | 中 |
| 4 | **帮助中心** | DSM 说明（文章/教程/FAQ/兼容性） | 桌面加「使用帮助」应用：使用指引 + 常见问题 + **AI 问答入口**（我们能直接答，DSM 只能给文章） | 低 |
| 5 | **对外分享链接** | 共享文件夹可生成链接 + 有效期 | 文件页右键「生成外链」：有效期 + 密码 + 访问日志；只读、可撤销 | 中（有合规问题，见 §7） |
| 6 | **收藏夹 / 最近访问** | Universal Search 书签 + 搜索历史 | 文件页左侧加「收藏」「最近」；桌面搜索框记历史 | 低 |
| 7 | **批量打包下载 / 解压** | Compress / Extract | 文件页多选后「打包下载」；回收站里对上传的压缩包提供解压 | 低-中 |
| 8 | **密码策略 + 登录失败自动封禁** | 密码强度/过期/历史；多次失败自动封 | 密码最少位数+过期提醒+历史不重复；连续失败 N 次锁定 X 分钟 | 低 |
| 9 | **个人目录配额** | 卷/用户配额 | 我们已有个人空间（`personal_root`）→ 加配额与用量条 | 低 |
| 10 | **全局搜索升级** | Spotlight 预览 + 应用索引 + 搜索历史 | 搜索结果按来源分组（文件名/正文/图谱实体），悬停出预览浮层 | 中 |
| 11 | **权限报告** | 共享权限报告（谁能访问什么） | 管理台加「授权总览」：某人能看哪些目录、哪些源没人授权、离职账号残留授权 | 低-中 |
| 12 | **文件版本历史** | 快照 | 只对管理台/个人空间做"覆盖前存旧版"，别全量做 | 中 |

## 4. 可以超越 DSM 的地方（AI 化，DSM 结构上做不到）

1. **检索**：DSM 的 Universal Search 是「文件名 + 全文索引 + 模糊」；我们是**语义 + 图谱 + 重排**，
   还能答"这份规划的三阶段是什么"并给引用。
2. **问答带溯源**：引用到页/幻灯片 + 检索轨迹 + 反馈闭环，DSM 全无。
3. **文件即知识**：PPTX/扫描件 → 自动切块/向量/图谱（今天 tmp_ppt 的 5 个 PPT 已经能问答）。
4. **主动运维助手**：「昨天谁动了信息化管理」「哪些文件解析失败」「这个月新增了哪些规范」
   —— 用审计 + 轨迹 + 看板数据直接回答。
5. **自然语言执行**：「把知识库目录里上月新增的规范列出来并生成清单」→ 可执行动作。
6. **知识关系可视化**：实体归一后的图谱，DSM 完全没有对应物。

## 5. 明确不抄（避免把平台做成另一个 NAS）

磁盘/RAID/Btrfs 校验/SMART/固件/UPS/休眠/风扇灯效、网卡/OVS/VPN/DDNS/端口转发、
证书与 Let's Encrypt、QuickConnect、iSCSI/SAN Manager、媒体索引与视频转码、
快照复制与异地备份、AFP/FTP/NFS/Rsync 服务端、套件市场与第三方套件。

理由：这些是「存储设备」职责，DSM 已经在做且做得比我们好；我们做会变成重复造轮子。
我们的定位：**挂在 NAS 上的「文件 + 知识 + AI」层**。

## 6. 优先级建议

| 批次 | 内容 | 理由 |
|---|---|---|
| **P0（1 个迭代内）** | 通知中心、平台运行状态页、任务与计划中心、帮助中心（+AI 入口） | 都是"把已有能力显性化"，成本低；直接解决"看不懂平台状态/出事没人知道" |
| **P1** | 对外分享链接、收藏夹/最近、批量打包下载、密码策略与自动封禁、授权总览、搜索升级 | 提升日常使用效率与安全基线 |
| **P2** | 2FA、配额、文件版本历史、LDAP/AD 接入、通知外发渠道 | 依赖客户要求或规模 |
| **不做** | §5 全部 | 定位不同 |

## 7. 需要拍板的三个问题

1. **对外分享链接**做不做？涉及把内网文件发给供应商/微信群，合规与水印要一起设计。
2. **通知走什么渠道**：站内 / 飞书（已有 bot）/ 邮件 / 企业微信？飞书最省事。
3. **平台运行状态页给谁看**：仅管理员，还是所有用户都能看到"服务是否正常"（出问题时全员需要知道）。
