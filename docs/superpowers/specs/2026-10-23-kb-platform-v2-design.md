# 企业知识平台 2.0 · 产品设计文档

> 定位：**带 AI 的企业 NAS**。员工在局域网里用浏览器访问，像用 Windows 资源管理器一样浏览、预览、上传、管理文件；同时由一个会用工具的智能体，在同一入口里完成「找文件」和「问内容」。
>
> 本文件是产品与技术的共同基线。实现计划另见 `docs/superpowers/plans/`。

---

## 1. 一句话说清

把「文件服务器 + 网盘 + 企业知识库 + AI 助手」合成一个网页产品：

- 登录后是一个**功能桌面**，不是一堆后台菜单；
- **文件**页像 Windows 资源管理器，能看、能搜、能传、能改；
- **AI** 页只有一个对话框，但背后是智能体：它会自己判断该按文件名找、还是按内容找，拿不准就问你；
- **管理台**管账号、目录读写权限、存储接入、模型接入、审计。

---

## 2. 用户与场景

| 角色 | 典型诉求 |
|---|---|
| 普通员工 | 找上周那份验收单；看某份制度里怎么规定的；把文件传到项目目录；问 AI「三级子企业能不能自建机房」 |
| 部门负责人 | 管理本部门目录的读写授权；看谁上传/删除了什么 |
| 管理员 | 建账号、分配目录权限、接入 NAS 与模型、处理回收站、看审计与运行状态 |

代表性场景（验收时按这几条走）：

1. 员工登录 → 桌面 → 点「文件」→ 进入自己的个人空间 → 上传 3 个文件 → 列表立即出现，几秒后可被搜到。
2. 员工在文件页顶部搜索框输入「验收单」，**边输边出结果**（300 ms 内），结果只包含他有权限的目录。
3. 员工在 AI 框里问「上个月的验收单里，验收结论是怎么写的？」→ 智能体先找文件，再读内容，回答并给出来源；若歧义，先反问「你要找文件，还是查条款？」。
4. 管理员把「项目管理/在建项目」目录授予张三**可写**，张三能上传、重命名、移动；对「财务」目录只给只读，删除按钮置灰。
5. 张三误删一个目录 → 进回收站 → 自己可恢复；彻底删除只有管理员能做。

## 3. 目标 / 非目标 / 反目标

### 目标

- **像本地一样**：目录树、列表/图标视图、多选、拖拽、右键菜单、回收站。
- **快**：文件名搜索 300 ms 内出结果；常用目录打开 1 s 内；AI 首字 3 s 内（本机模型）。
- **一个入口**：文件与 AI 不再分家；搜索框既搜文件也能发起提问。
- **权限可信**：所有列表、搜索、预览、下载、AI 检索都在服务端过权限；越权一律 404。
- **可运维**：单机部署、开机自启、日志与审计齐全，管理员不用碰命令行。

### 非目标（本期不做）

- 在线协同编辑 Office、多人同时编辑同一文件；
- 文件版本历史（只做回收站）；
- 公网暴露、移动端 App（页面做响应式，但以桌面浏览器为主）；
- 去重、块级增量同步、桌面同步客户端；
- 复杂审批流、水印、DLP。

### 反目标（做到这些也算失败）

- AI 因为「模型知道」而给出无来源的答案；
- 为了炫技把登录页/桌面做得很卡，低配办公机打不开；
- 权限只在前端隐藏按钮、接口却能越权；
- 上传大文件把服务卡死，或断点续传不可用；
- 目录里有 10 万文件时列表直接白屏。

## 4. 产品形态

### 4.1 登录页

- 全屏深色科技感：低饱和度深蓝黑底 + 缓慢流动的光带/网格，**动效克制**（CSS/Canvas，不加载大视频）。
- 居中玻璃质感卡片：产品名、账号、密码、记住我、登录按钮；错误提示就地显示，不弹窗。
- 左下角显示版本与「内网访问」标识；右下角可放一句安全提示。
- 无自助注册；忘记密码提示「联系管理员重置」。
- 首次登录强制改密（管理员建号时勾选）。
- 低配机降级：`prefers-reduced-motion` 时关闭动效。

### 4.2 功能桌面（登录后首页）

- 顶部：产品名、全局搜索框（Ctrl+K）、当前用户、退出。
- 中部：功能图标网格，按权限显隐：
  - **文件**（所有用户）
  - **AI 助手**（所有用户）
  - **知识图谱**（所有用户）
  - **文档看板**（所有用户；管理员可看全局）
  - **回收站**（所有用户看自己的；管理员看全部）
  - **管理台**（仅管理员）
- 每张卡片是一个大图标 + 名称 + 一句说明；悬停有轻微上浮与光晕。
- 底部：最近访问的 6 个文件/对话（可关闭），方便第二天接着干。
- 桌面不是可自由拖拽的图标桌面；图标顺序固定，避免用户把入口拖丢。

### 4.3 文件页（核心）

布局：左侧目录树 / 中间文件区 / 右侧可折叠详情。

- **目录树**：个人空间置顶，下面是管理员授权的共享目录；只显示有读权限的节点。
- **工具栏**：上传、新建文件夹、排序、视图切换（列表/图标）、刷新；搜索框（见 §6）。
- **面包屑**：可点击回退；支持「在资源管理器中打开路径」的复制。
- **文件区**：多选（Ctrl/Shift）、拖拽上传、拖拽移动、右键菜单（预览、下载、重命名、复制、移动到…、删除、复制路径）。
- **列表列**：名称、修改时间、类型、大小、上传者（可选）；支持按列排序。
- **上传**：底部传输面板，显示进度/速度/剩余时间；支持多文件、文件夹上传、失败重试、刷新后续传（分片）。
- **预览**：双击或右键预览，全屏浮层；左右方向键切换同目录文件；Esc 关闭。
- **回收站**：独立页；显示原路径、删除人、删除时间、大小；可恢复/彻底删除（管理员）。
- **空状态**：目录为空时给「拖文件到这里上传」的提示，而不是一片空白。

### 4.4 AI 助手页

- 左侧会话列表（新建、重命名、删除），右侧对话流。
- 输入框支持：文字、拖入文件（作为上下文）、`@文件` 选择已上传文件。
- 回答形态：
  - 纯文字结论；
  - 文件卡片（名称、路径、大小、修改时间、缩略图/类型图标），可直接预览或「在文件中定位」；
  - 引用片段（文件名 + 页码/段落），点击跳到预览对应位置（能定位到页的格式）。
- 运行过程可见：`正在查找文件…` / `正在阅读 3 份文档…` / `正在整理答案…`，用状态条而不是转圈。
- 歧义时输出**澄清卡片**：一句话 + 2~4 个可点选项（「按文件名找」「按内容找」「都要」）。
- 模型选择器放在输入框旁（默认「自动」）；管理员可禁用某些模型。
- 所有回答带「来源」，无来源时明确说「没有在授权目录中找到依据」。

### 4.5 知识图谱 / 文档看板

- 保留现有能力：概览自动加载、点击展开邻居、搜索节点、状态页签与分页。
- 视觉与新设计语言统一（深色、细线、低饱和强调色）。

### 4.6 管理台

分区：概览 / 用户与权限 / 存储接入 / 模型接入 / 回收站 / 审计 / 系统状态。

- **用户**：新建、**Excel 批量导入**、停用、重置密码、设配额、强制改密。
- **权限**：左侧目录树 + 右侧用户，勾选「只读 / 可写」；支持按部门批量；权限变更写审计。
- **存储接入**：新增/编辑存储源（SMB、本机磁盘；WebDAV/S3 预留），测试连接、设默认、设个人空间根目录。
- **模型接入**：新增提供商（Ollama、OpenAI 兼容）、填 Base URL/Key、拉模型列表、测试、设默认对话/嵌入模型。
- **回收站**：保留天数、批量恢复/清理。
- **审计**：登录、上传、下载、删除、权限变更、AI 调用（谁、何时、问了什么、命中哪些文件、用了哪个模型）。
- **系统状态**：磁盘、索引队列、解析进度、模型健康、最近错误。

### 4.6.1 批量导入用户（Excel）

**模板列**（提供「下载模板」按钮，带示例行与填写说明）：

| 列 | 必填 | 说明 |
|---|---|---|
| 用户名 | 是 | 登录名，唯一，4~32 位字母/数字/下划线 |
| 姓名 | 否 | 展示名，空则用用户名 |
| 部门 | 否 | 展示与批量授权用 |
| 角色 | 否 | `user`（默认）/ `admin` |
| 初始密码 | 否 | 留空则生成 12 位随机密码 |
| 空间配额GB | 否 | 留空表示不限 |
| 共享目录 | 否 | 如 `信息化管理/AI知识库`；同一用户多行即多条授权 |
| 权限 | 否 | `read`（默认）/ `write`，与「共享目录」成对 |

**流程**：

1. 上传 `.xlsx`（`.xls` 自动经 LibreOffice 转换）→ 服务端解析并**预检**，不写库。
2. 预检页展示：总行数、可导入、错误行（标红并给原因：用户名重复、目录不存在、权限值非法、密码过短等）。
3. 选择策略：「仅导入合法行」或「有错误则全部放弃」；已存在的用户名默认**跳过**，可选「更新资料（不覆盖密码）」。
4. 确认导入 → 显示成功/失败条数；生成「账号-初始密码」CSV，**只可下载一次**（密码不落明文库）。
5. 导入完成写审计：操作人、文件名、SHA-256、成功/失败条数、耗时。

**约束**：单次 ≤ 5000 行；导入过程不阻塞其他请求；重复导入不会重复建号；所有新用户首次登录强制改密（可关）。

## 5. 权限模型

- **默认拒绝**：用户对任何目录默认不可见；管理员显式授权。
- **取消「涉密目录」**：2.0 不再使用 `dir_scopes` 的特殊限制。可见性完全由 `grants` 决定——能看到的文件就能预览/下载，AI 也按同一套授权过滤。升级时保留旧数据但不再生效，并在升级说明中告知管理员。
- **授权粒度**：`(存储源, 目录)`，两种级别：`read`、`write`；`write` 隐含 `read`。
- **继承**：授权目录下的子目录自动继承；子目录可单独加授权，但不能收回父级（避免歧义）。若要「父可读、子不可读」，用「排除」规则——本期不做，改为把子目录移到别的共享。
- **深层授权的导航**：用户只被授权 `A/B/C` 时，目录树显示 `A`、`A/B` 作为**导航占位**（只有名字，不能列出同级兄弟），以便进入 `C`；不泄露同级目录。
- **写权限边界**：
  - 授权根本身不可重命名/删除/移动（防止授权悬空），其内部可以；
  - 移动/复制要求**源与目标都有写权限**；
  - 移动授权根下的子目录后，子授权随新路径前缀迁移；
  - 删除一律进回收站，彻底删除仅管理员。
- **部门批量授权**：v2.0 为**一次性快照**（按 `users.dept` 筛选后逐人写 grants）；不做组织架构继承，调部门/离职需管理员重新授权。
- **个人空间**：每个用户自动拥有 `个人空间/<用户名>` 的读写权限，其他人不可见；管理员可查看（审计/交接），查看行为写审计。
- **管理员**：全量读写，但所有写操作与查看个人空间都写审计。
- **服务端强制**：列表、搜索、预览、下载、上传、移动、删除、AI 工具调用全部在服务端校验；前端隐藏按钮只是体验，不是安全边界。
- **路径安全**：所有路径规范化后必须落在授权根内；拒绝 `..`、符号链接逃逸、UNC 注入。
- **配额**：按用户/部门设上传上限（可选），超限返回 413 并提示。

## 6. 搜索：文件名秒搜 + 内容检索 + 智能体

### 6.1 三层检索

| 层 | 用途 | 数据 | 目标延迟 |
|---|---|---|---|
| L1 文件名/路径 | 输入即出，Everything 式 | 全量路径索引（含目录） | < 300 ms |
| L2 内容检索 | 关键词 + 语义找段落 | 解析后的 chunk（FTS + 向量 + 图谱） | < 1.5 s |
| L3 智能体 | 多步：找文件→读内容→回答 | 调 L1/L2 + 取全文 | 首字 < 3 s |

### 6.2 文件名索引怎么做

- **自建路径索引**（主方案）：扫描器把每个存储源的目录与文件写入 `fs_entries`，`name` 与 `path` 进 FTS5（中文用二元组，英文/数字用前缀）；增量按目录 mtime + 文件 mtime/size 更新，扫描周期 1~5 分钟可配。
- SMB 共享**用不了** Everything 的 MFT/USN（那是 NTFS 本地特性），所以不依赖 Everything。
- **可选插件**：若平台跑在 Windows 且本机有 Everything，可接它的 HTTP API，仅用于本机磁盘，作为补充而非依赖。
- 网页上传/重命名/删除后**立即更新索引**，不用等扫描。
- 规模：100 万条路径在 SQLite FTS5 下单机可接受；列表与搜索都分页。

### 6.3 搜索交互

- 文件页搜索框：输入即搜文件名（L1）；结果分组「文件 / 文件夹」，支持「只搜当前目录」开关。
- 按 `Enter` 或点「问 AI」：把当前输入交给智能体（L3），对话在右侧抽屉展开，不离开文件页。
- 全局 `Ctrl+K`：任意页面打开命令面板，先给文件名结果，底部固定「问 AI：<输入>」。
- L2 内容搜索作为独立 tab（文件页搜索框的「搜内容」），也由智能体自动调用。

## 7. AI 智能体

### 7.1 为什么不是「一个模型 + 一段提示词」

用户一句话可能包含三种意图：找文件、查内容、做归纳。必须由**工具调用循环**完成，而不是让模型凭空回答。

### 7.2 工具集（全部服务端鉴权）

| 工具 | 作用 | 关键参数 |
|---|---|---|
| `find_files` | 按名称/路径/扩展名/时间找文件与目录 | `query`, `scope`, `ext`, `mtime_after`, `limit` |
| `list_dir` | 列目录 | `path` |
| `search_content` | 内容检索（FTS+向量+图谱融合） | `query`, `top_k`, `filters` |
| `read_document` | 取某文档全文或指定页/段 | `document_id`, `page_range` |
| `get_metadata` | 文件元信息、解析状态、知识点 | `document_id` |
| `ask_user` | 歧义澄清 | `question`, `options[]` |

- 循环上限 5 步；每步都 SSE 推送状态，前端显示「正在…」。
- 工具结果始终附带 `file_id/path/locator`，供引用与「在文件中定位」。
- **ID 契约**：`file_id` = `fs_entries.id`（所有文件与目录）；`document_id` = `catalog.id`（仅可解析文档）。引用同时保存 `file_id` 与当时的路径快照；文件移动/重命名后按 `file_id` 解析，路径快照仅作展示。
- **权限在工具层校验**，模型无法通过构造参数越权；越权返回空结果并记审计，不向模型泄露「存在但无权」。

### 7.3 意图路由

1. 先做规则判断（快、便宜）：
   - 带引号、扩展名、`*`、路径分隔符 → `find_files`；
   - 明确问句（「怎么规定」「为什么」「总结」）→ `search_content`；
   - 「找/哪份/文件」+ 时间/部门 → `find_files` 优先。
2. 规则不确定 → 交给支持 function calling 的模型决策。
3. 仍不确定 → `ask_user` 给 2~4 个选项，不猜。
4. 模型不支持工具调用时，退化为「规则路由 + 单轮检索」，并在管理台标注该模型能力。

### 7.4 回答规范

- 先结论、后依据；文件卡片与引用片段分离。
- 每个事实性结论必须挂引用；找不到依据时直说，并建议换关键词或放宽目录。
- 不输出用户无权查看的路径/文件名；引用中的路径按授权裁剪。
- 多轮上下文只保留当前会话；会话按用户隔离，管理员不可读他人会话内容（只审计调用记录）。

## 8. 文件预览

| 类型 | 方案 |
|---|---|
| PDF | PDF.js，服务端支持 Range 请求；大文件按页加载 |
| 图片 | 浏览器原生；缩略图服务端生成并缓存 |
| 文本/代码/日志 | 纯文本高亮，超过 2 MB 截断并提示下载 |
| Office（docx/xlsx/pptx） | LibreOffice headless 转 PDF，缓存转换结果；转换队列限并发 |
| 老格式（doc/xls/ppt） | 同 Office，先转换 |
| 音频/视频 | 浏览器原生播放（Range） |
| 压缩包 | 只列目录，不允许在线解压（防 zip bomb） |
| 其他 | 显示元信息 + 下载 |

预览页支持：同目录左右切换、缩放、下载、复制路径、在 AI 中提问（把当前文件作为上下文）。

## 9. 存储接入（通用 NAS / 云盘）

统一接口 `StorageAdapter`：

```
list(path) / stat(path) / open_read(path) / open_write(path)
mkdir / rename / move / copy / delete
exists / capabilities
```

首批实现：

- **SMB/CIFS**（公司 NAS，主场景）：Windows 下用 UNC 路径 + 服务账号凭据；只读/可写由授权决定。**同一台 NAS 主机只支持一套凭据**（Windows 会话级限制）；需要多套凭据时按主机拆分存储源。
- **本机磁盘**：用于个人空间或小规模部署。
- **WebDAV**（第二期）：群晖/Nextcloud 等。
- **S3 兼容**（预留，不做 UI）。

要点：

- 存储源由管理员配置，凭据加密存储；测试连接后才可启用。
- **一个存储源对应一个共享根**（UNC 共享 / 盘符 / WebDAV 根）；需要多个共享就建多个存储源。目录树按存储源分组展示。
- 个人空间放在管理员指定的可写根下（如 `\\nas\...\_personal\<用户名>`），首次登录自动创建。
- 回收站：软删除移动到同存储源的 `_trash/<日期>/<原相对路径>`，保留 30 天（可配）；跨存储源移动走流式复制+删除。
- 上传：5 MB 分片、断点续传、服务端临时文件 + 原子改名；校验大小与可选 SHA-256。
- 不做文件锁；同一文件并发写以「最后完成者覆盖」为准，并在传输面板提示冲突。

## 10. 内容索引与知识库（沿用并扩展现有能力）

- 两阶段：Tier 1 切块 + FTS + 向量；Tier 2 LLM 提炼 + 图谱。
- 触发：网页写入立即入队；NAS 侧变更由扫描发现；删除/移动同步清理索引。
- 扫描件：存量不自动 OCR（136 秒/页），标「待 OCR」；新上传的扫描件自动 OCR，限页数/时长。
- 解析失败：保留原因，可在文件详情里看到（管理员可见完整原因）。
- 只有「可解析文档」进内容索引；图片/音视频只进路径索引与预览。

## 11. 技术架构

```
浏览器（LAN）
  │ HTTPS/HTTP
  ▼
FastAPI + uvicorn（单进程；按需拆 worker）
  ├── 认证/会话（cookie） + Bearer Token（外部智能体）
  ├── 文件服务：StorageAdapter(SMB/本地/WebDAV)
  ├── 路径索引：fs_entries + FTS5
  ├── 内容检索：FTS5 + 向量 + 图谱 + RRF
  ├── 智能体：工具调用循环 + SSE
  ├── 模型网关：Ollama / OpenAI 兼容
  └── 任务队列：索引 / 提炼 / 预览转换
        │
        ├── SQLite（WAL）：元数据、索引、会话、审计
        ├── 向量库（现有实现）
        └── 文件缓存：预览 PDF、缩略图
```

- 前端：继续**无构建**的原生 JS，但拆分为模块（`fs.js`、`chat.js`、`admin.js`…），由 `index.html` 按页懒加载；避免在办公机上引入 Node 构建链。
- 后端：在现有 `kbplatform` 上增量开发；现有 `/api/v1/documents`、`/query`、`/search`、图谱接口保持兼容，外部智能体（WorkBuddy）不受影响。
- 数据库：SQLite 继续用；单表超过 500 万行或并发写明显冲突时再评估 PostgreSQL。

## 12. 数据模型（新增/变更）

```sql
-- 存储源
CREATE TABLE storage_sources (
  id INTEGER PRIMARY KEY,
  name TEXT UNIQUE NOT NULL,          -- 展示名
  kind TEXT NOT NULL,                 -- smb | local | webdav
  root TEXT NOT NULL,                 -- UNC / 盘符 / URL
  username TEXT, secret_enc TEXT,     -- 凭据加密
  writable INTEGER DEFAULT 0,
  personal_root TEXT,                 -- 个人空间根（相对 root）
  enabled INTEGER DEFAULT 1,
  created_at REAL
);

-- 文件/目录路径索引（全量，不只文档）
CREATE TABLE fs_entries (
  id INTEGER PRIMARY KEY,
  source_id INTEGER NOT NULL,
  path TEXT NOT NULL,                 -- 规范化绝对路径/相对路径
  parent TEXT NOT NULL,
  name TEXT NOT NULL,
  is_dir INTEGER NOT NULL,
  size INTEGER,
  mtime REAL,
  ext TEXT,
  updated_at REAL,
  UNIQUE(source_id, path)
);
CREATE INDEX idx_fs_parent ON fs_entries(source_id, parent);
CREATE INDEX idx_fs_name   ON fs_entries(name);

-- 授权：read/write
CREATE TABLE grants (
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL,
  source_id INTEGER NOT NULL,
  subpath TEXT NOT NULL DEFAULT '',   -- '' = 整个共享
  can_write INTEGER DEFAULT 0,
  granted_by INTEGER,
  created_at REAL,
  UNIQUE(user_id, source_id, subpath)
);

-- 回收站
CREATE TABLE trash (
  id INTEGER PRIMARY KEY,
  source_id INTEGER NOT NULL,
  original_path TEXT NOT NULL,
  trash_path TEXT NOT NULL,
  name TEXT NOT NULL,
  is_dir INTEGER DEFAULT 0,
  size INTEGER,
  deleted_by INTEGER,
  deleted_at REAL,
  restored_at REAL
);

-- 上传会话（断点续传）
CREATE TABLE upload_sessions (
  id TEXT PRIMARY KEY,
  user_id INTEGER NOT NULL,
  dest_path TEXT NOT NULL,
  total_size INTEGER,
  chunk_size INTEGER,
  received INTEGER DEFAULT 0,
  sha256 TEXT,
  status TEXT,                        -- uploading|merging|done|failed
  created_at REAL, updated_at REAL
);

-- 对话
CREATE TABLE conversations (
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL,
  title TEXT,
  created_at REAL, updated_at REAL
);
CREATE TABLE messages (
  id INTEGER PRIMARY KEY,
  conversation_id INTEGER NOT NULL,
  role TEXT,                          -- user|assistant|tool
  content TEXT,
  tool_calls TEXT,                    -- JSON
  citations TEXT,                     -- JSON
  created_at REAL
);
```

现有 `catalog` 保留为「可解析文档」的索引表，通过 `path` 与 `fs_entries` 关联。`fs_entries.id` 即对外的 `file_id`；移动/重命名时同时更新 `fs_entries` 与 `catalog` 的路径。

**迁移**：现有 `user_scopes` 一次性导入 `grants`（默认只读）；`grants` 成为唯一权限源，`/documents`、`/search`、`/query`、`/graph/*` 与外部智能体统一改为按 `grants` 过滤。上线前做一次全量对账（旧 scope 与新 grants 的可见文件集合必须一致）。

## 15. 部署与运维

- **服务器**：Windows Server（现有环境），NAS 通过 SMB 挂载；平台以计划任务/服务方式随登录启动。
- **账号**：服务账号需对授权目录有读写权限；凭据保存在 Windows 凭据管理器或加密配置。
- **HTTPS**：内网可先 HTTP；如公司有证书，用反向代理（Caddy/Nginx）加 TLS。
- **备份**：每日备份 SQLite（在线备份 API）+ 配置导出；文件本身由 NAS 快照负责。
- **升级**：静态资源带版本号；后端升级前自动备份数据库；升级过程可在管理台看到版本与迁移记录。
- **监控**：管理台系统状态页 + 心跳文件；异常写日志并在桌面提示管理员。

## 17. 风险与对策

| 风险 | 对策 |
|---|---|
| SMB 目录大、列目录慢 | 列表走路径索引（DB），后台异步刷新；分页与虚拟滚动 |
| 100 万文件索引占空间/变慢 | 只索引元数据；定期 VACUUM；按存储源分表/分区预留 |
| Office 转换吃 CPU | 限并发 1~2；结果缓存；转换失败降级为下载 |
| 本机 9B 模型工具调用不稳 | 规则路由兜底；管理台标注模型能力；可选更强云端模型 |
| 用户误删/误覆盖 | 回收站 + 删除审计；覆盖上传需确认 |
| 权限配置复杂 | 目录树勾选 + 部门批量 + 变更审计；提供「以该用户视角预览」 |
| 大文件上传中断 | 分片 + 续传 + 校验；失败可重试 |
| 端口/凭据运维 | 单机 supervisor + 心跳；管理台显示服务与 NAS 连接状态 |

## 18. 留给实现者的决定（我的建议，已写入本文）

1. 前端继续无构建原生 JS，模块化拆分，不引入 React/Vue。
2. 路径索引自建，Everything 仅作可选插件。
3. 软删除一律进回收站，彻底删除仅管理员。
4. 预览用 LibreOffice 转 PDF，不引入 OnlyOffice。
5. 个人空间放在指定的可写共享下，按用户名隔离。
6. 智能体循环上限 5 步，工具全部服务端鉴权。
7. 现有 API 与外部智能体接入保持兼容，2.0 只做增量。
8. 取消「涉密目录」：权限即边界，可见即可预览/下载；旧 `dir_scopes` 数据保留但不再生效。

这些都可以被推翻；推翻哪条，改动会写进本文件的修订记录。
